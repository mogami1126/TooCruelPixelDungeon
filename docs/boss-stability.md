# 英烈1.0.2 Boss稳定性修复

本补丁基于原版v1.0.2，保留旧玩法与修改器。修复国王阶段死亡遗漏、天狗快速动画永久等待，并增加受控的移动等待恢复。

## 改动

- 国王KingDamager只扣阶段护盾，超出盾量的部分不再扣受保护的HP；波次门槛按当前HT与12/18次扣盾计算。
- 切换第三阶段时重新检查死亡；国王act能补结算旧存档中0血的第三阶段国王。die增加单实例重复调用保护，仍使用原皇冠、解封与死亡流程。
- 天狗先更新逻辑位置，再把sprite放到最终逻辑格。快速动画前先设移动标记，让同步完成回调能清掉它；动画被替换及idle时释放等待。
- 天狗sprite构造时先建立单帧idle，再播放入场动画，避免快速动画跳过入场时仍按整张256像素纹理定位，导致121像素的显示偏移。
- Actor记录正在等待移动的角色与开始时间。渲染线程在等待超过10秒时尝试恢复一次；菜单等待期间增加手动恢复按钮。恢复仅取消移动视觉、校准sprite和通知等待线程，不调用攻击/投射物回调、不调用next。

## 验证

使用JDK25的`javac --release 8`编译SPD-classes、services与core，共1098个源码文件，成功。依赖沿用项目版本：libGDX与freetype 1.10.0、org.json 20170516。

Windows下可用`python tools/compile_core.py`重复核心编译；脚本从Maven Central读取指定版本依赖，缓存与编译结果写入`.research`。

运行`python tools/boss_regression.py`。该脚本抽取当前源码中的15个方法体，使用最小引擎桩生成并运行Java回归探针，覆盖：

- 天狗普通、快速与被中断的跳跃动画；
- 恢复的10秒门槛、视觉校准、一次限制与拒绝无移动等待的情况；
- 国王普通/加强模式、非整除HT、放大后波次门槛、int最大HT；
- 阶段扣盾溢出保护、第三阶段死亡与0血阶段转换补结算。

完整Android Gradle调试构建已通过：Gradle运行使用JDK11，Java源码编译使用JDK8，SDK API30和Build Tools30.0.2。APK已安装到本机Pixel7 API36模拟器。

模拟器辅助测试已跑通MMO天狗（快速/普通动画）、MMO国王、加强国王满场召唤失败；天狗正常到11层，国王掉落皇冠并到21层。测试使用不死和额外攻击伤害；满场测试用255个中立静止怪物占据生成位置。它验证真实Boss阶段和死亡流程，不代表正常装备平衡或全部93个修改器组合。

用户指出自动测试第二阶段黑屏且仍跳伤害。检查发现测试工具跳过走路进入竞技场，却未移动角色；已在自动切第二阶段时把测试角色移入竞技场并重算视野。此问题属于测试工具，不能用此前的自动通过日志证明第二阶段画面正常。详细使用说明见[boss-test-tools.md](boss-test-tools.md)。

## 恢复边界

本次看门狗只恢复已确认的移动等待，不恢复未提交的攻击/投射物回调或正在执行的CPU循环。此类卡顿仍可使用原Debug记录线程状态，不能安全地统一跳过回合。国王状态修复由Boss自己的逻辑执行，不依赖超时。

建议实机重点检查：快速动画开关、天狗两阶段与读档；普通/加强国王加MMO、满格召唤失败、0血残留旧档，以及死亡后皇冠和通往21层的出口。
