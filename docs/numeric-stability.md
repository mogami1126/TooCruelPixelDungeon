# MMO数值问题进度

## 已修：血量上限及治疗药水溢出

Hero.updateHT原先先以int计算基础血量，根骨之戒乘法后再以int加体质灵药；升级补血也使用int加法。极大值会在后续加法中越过2147483647，变成负数。

Healing.act原先在Math.min限制到HT之前计算HP+本次治疗，已经可能溢出。累计治疗储备和每回合治疗量的相加也有同类风险。

当前修改使用double计算血量上限，long计算补血及储备的加法，再限制到int可表达范围。正常血量公式与治疗节奏保留；超范围血量饱和到2147483647。这是现有int存档/战斗模型的止血措施，不能实现真正无上限血量，也不修复已损坏存档中的历史负数。

`python tools/health_regression.py`直接抽取当前Hero.updateHT与Healing的方法，使用最小依赖桩验证：普通治疗、高血量治疗、储备叠加、治疗步长溢出、无限根骨倍率加体质灵药、等级基础血量溢出、卸下戒指。测试没有不死逻辑；全部通过。完整Android调试构建通过。尚未用模拟器真实饮药复现高血量边界，因此不把探针结果称为实机验收。

## 待修或待确认

- 其他补血入口：食物、天赋、圣杯等仍有HP加法，不能宣称所有补血溢出已经消除。
- 闪避/免伤异常：命中使用随机对抗，闪避戒指显示的百分比是属性增幅，不是必定躲避概率。极值还需追踪装甲倍率、int转换、伤害减免与不同伤害来源，尚不能认定用户遇到的是哪一环。
- 防具失效：固定防御区间与MMO怪物指数成长尺度不同，需要设计相对减伤和成长曲线；这属于平衡及机制调整。
- 速度卡死：极速/狂怒戒指指数倍率可以成为Infinity，时间消耗可以变为0；Actor.spend使用float，靠近整数还会舍入，极小正耗时也可能不推进时间。移动动画看门狗无法修复这类调度问题。
- 敌人剩1血：Mob.die里不倒翁修改器会故意保留1血、传送并加盾，但正常只触发一次。它不能解释所有重复剩1血现象；还需分辨复活、升华、伤害溢出及具体攻击来源。
- 国王死亡、天狗跳跃等待及快速动画贴图定位：见boss-stability.md，已有独立修复及模拟器辅助验证。
