## 本次新增验证

执行 `python tools/scheduling_interaction_regression.py`，通过。抽取当前完整 Actor、新数值类型、Char.spend、Char.hit、RingOfTenacity.damageMultiplier；其他引擎依赖为桩。输出在 `.research/scheduling-interaction/output.txt`。

- 实际 Char.spend：普通 1 回合不变；微小正成本限制为 1/64；100 回合成本限制为 64；零耗时保留；-0.25 退款保留。
- 实际 Actor：31 次连续继续执行的零耗时动作不触发保护；32 次触发一次并推迟 1/64 回合；10 次有限退款总计 -2.5 回合且不触发保护；100 次交替零耗时/正耗时正常累计 50 回合且不触发保护。
- 实际 Char.hit：传入饱和后的命中/闪避属性，命中越过阈值直接成功；双方都越过阈值则闪避优先，不调用随机数。这是原有阈值机制，本 PR 没修改该方法；不等于已经覆盖 Hero、护甲、MMO 和随机数的完整链路。
- 实际韧性倍率：+100000、HP=50/HT=100 时为 0；无加成为 1。基线使用 Math.pow 的对应表达式也会下溢为 0，属于既有数值边界，不将它记为新增回归。

合法长零耗时链也会在第 32 次继续执行时被推迟。这是策略边界，探针不能证明所有流水精英或其他挑战组合都能接受该顺序变化。尚无本次引入的可复现游戏故障，不据此擅改保护阈值。
